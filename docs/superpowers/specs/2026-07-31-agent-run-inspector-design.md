# Agent运行侧栏渐进式时间线设计

## 目标

将右侧“本次运行”从静态日志列表改为可交互的渐进式时间线。默认让普通用户快速看懂Agent做了什么；点击节点后，在原位置展开必要的脱敏调试信息和安全操作。

本次只优化现有运行侧栏，不新增评测中心、不改变聊天主布局、不开放任意节点改参或从中间状态恢复执行。

## 信息结构

侧栏保留三层信息：

1. 运行概览：状态、进度、总耗时、工具调用次数和简短run ID。
2. 过程时间线：按真实执行顺序展示系统、记忆、模型、Skill、工具、MCP和确认节点。
3. 节点详情：选中节点在原位置展开，不再把详情放到时间线底部。

每个折叠节点只显示：

- 人话标题；
- 类型和状态；
- 耗时；
- 是否可展开；
- 失败、等待确认、后台处理中等关键状态。

展开后按需显示：

- “为什么执行”：由前端根据节点类型和公开状态生成稳定说明，不展示模型思维链；
- 公开输入概览；
- 结果摘要；
- 错误码和脱敏错误说明；
- 类型专属信息；
- 当前节点可执行的安全操作。

## 类型专属信息

### 模型

显示模型名称、接口协议、步骤耗时和公开结果状态。不得展示完整系统提示词、隐式推理或API Key。

### 工具与联网搜索

显示工具名称、公开参数摘要、结果数量、耗时和结果摘要。联网搜索额外显示查询词及可跳转的来源信息。

### MCP

显示服务器、工具、风险等级、审批结果、公开输入和输出摘要。写操作继续遵守现有确认流程。

### 记忆

召回节点显示采用了多少条记忆及具体公开内容；整理节点显示新增、更新、删除或“没有产生长期记忆变更”。提供“管理长期记忆”跳转。

### Skill

显示Skill名称、版本、来源、所需工具和所需MCP，并提供“查看Skill”跳转。

### 失败节点

错误信息必须经过现有trace脱敏。可恢复的记忆操作使用现有重试接口；其他失败节点提供“重新运行本轮”，避免从中间节点重放造成重复写入。

## 交互

- 单击节点：展开当前节点并收起之前节点。
- 再次单击已展开节点：收起。
- “复制详情”：复制该节点的公开信息，不包含私密details或密钥。
- “查看记忆”“查看Skill”“查看工具”：跳转到对应管理页面。
- “重新运行本轮”：仅在失败且无法安全单步重试时出现。
- 键盘操作：节点使用button，保留焦点态、`aria-expanded`和关联详情区域。
- 运行中：自动选中最新的运行中、等待确认或失败节点，但不得覆盖用户主动选择。

## 数据流

后端继续输出现有安全trace结构：

- `kind`、`name`、`status`、`durationMs`；
- `inputSummary`、`outputSummary`、`errorCode`；
- 经过白名单控制的`details`。

如模型名称、协议、工具结果数量等必要字段尚未进入公开trace，只在后端trace白名单中补充最小字段。前端不得读取或展示原始请求体、完整模型响应、密钥、OAuth Token、未脱敏异常或隐藏提示词。

`ChatEvidenceDrawer`继续管理当前run、trace、引用和审批状态；`AgentTraceView`负责选择状态和时间线；节点详情拆为独立展示单元，类型映射和公开复制内容由纯函数生成，便于测试。

## 视觉规则

- 沿用现有黑白与青绿色状态色，不增加大面积彩色卡片。
- 时间线连线保持轻量，只有选中、失败、等待确认节点使用边框强调。
- 详情采用短段落和键值行，禁止直接堆原始JSON。
- 侧栏窄屏时保持单列，不产生横向滚动。
- 不使用“大标题＋小字号解释段落”模板；说明直接进入节点标题、字段标签和操作。

## 错误与空状态

- 无trace：显示“本次回答没有运行记录”。
- 输入或输出为空：隐藏对应字段，不再显示“无”占位卡。
- 未知节点类型：显示安全的通用标题、状态、耗时和已有公开摘要。
- 复制失败：通过现有Toast反馈。
- 跳转目标不存在：隐藏跳转按钮。
- 重试失败：保留失败节点并更新错误提示，不伪装为成功。

## 验收标准

1. 点击任一节点后，详情在该节点下方原地展开。
2. 模型、工具、MCP、记忆、Skill和失败节点均有对应的人话信息结构。
3. 不再出现底部孤立的“公开输入/结果摘要”静态卡。
4. 复制内容不包含Key、Token、完整请求体或隐藏提示词。
5. 记忆和Skill节点可跳转到相应页面。
6. 可安全恢复的失败节点能重试；其他失败节点能重新运行本轮。
7. 实时trace更新后，用户未主动选择时自动跟随当前节点；主动选择后不抢焦点。
8. 现有运行进度、审批、引用、任务计划和后台记忆状态不回归。
9. 前端构建、现有`tests/check_*.py`及新增交互契约测试全部通过。
