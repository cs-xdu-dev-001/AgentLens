# 模型配置工作台精简设计

## 目标

让用户在一个页面内快速判断“当前选中了什么模型、是否可用、使用什么协议、下一步能做什么”，同时保留创建、编辑、测试、设为默认和删除能力。

## 信息架构

- 左侧列表固定承担选择任务：配置名称、模型ID、状态、默认标记。
- 右侧顶部只显示当前模型名称、模型ID、状态与默认标记。
- 右侧中部用无底色的两列定义列表展示提供商、模型类型、接口协议、接口地址和密钥配置状态。
- 模型类型与协议以能力标签呈现，只展示后端配置能够证明的事实，不推断上游是否支持工具或视觉。
- 连接检查结果在详情区内联显示真实耗时与服务端安全消息；Toast保留为辅助反馈。

## 操作层级

- “检查连接”为主要操作。
- “编辑”和“设为默认”为次级操作；已是默认时不渲染无效按钮。
- “删除”进入原生`details`更多菜单，继续使用现有确认框。
- 所有异步操作沿用`busyModelId`禁用保护。

## 视觉规则

- 延续纯白工作台，只用细分隔线、排版和间距建立层级。
- 移除标签和值的灰色底块，状态色仅用于状态圆点和连接结果。
- 缩短详情区纵向空洞，让信息和操作在首屏内聚合。
- 窄屏下列表与详情上下排列，操作可换行，不产生横向滚动。

## 非目标

- 不修改模型配置API、数据库字段或加密方式。
- 不新增无法从配置或测试结果验证的能力声明。
- 不重做模型创建/编辑表单。

## 验收

- 列表和详情没有大面积灰底文字块。
- 默认和可用状态不重复堆叠。
- 连接测试在详情内显示检查中、成功或失败、耗时与安全消息。
- 删除动作位于更多菜单，现有功能保持可用。
- 前端构建与全部`tests/check_*.py`通过。
