# 聊天空态交互优化设计

## 目标

修复新会话页面视觉重心下坠、标题与输入框割裂、空运行抽屉抢占空间、鼠标焦点描边过重的问题。保留现有功能与整体黑白风格，不重做聊天消息态。

## 已确认问题

- 欢迎标题和输入框被推到页面下半部，两者间距过大。
- 顶栏标题、操作按钮、左右侧栏、输入框形成多个互不关联的视觉块。
- 新会话仍可显示没有内容的运行抽屉，削弱输入主任务。
- 输入框高度、阴影和圆角偏重。
- 鼠标点击会留下夸张双层焦点描边，键盘焦点与鼠标焦点没有区分。

## 视觉方向

**Visual thesis**：克制的纸面工作台，以紧凑输入组为唯一视觉锚点，边框负责结构，阴影只提供轻微悬浮感。

**Content plan**：空态只保留欢迎语、输入框和必要输入控制；顶栏降噪；运行抽屉仅在存在运行内容时占据注意力。

**Interaction thesis**：新建对话立即回到干净输入态；鼠标点击不产生持久描边；键盘导航仍提供明确焦点；输入框聚焦时只做轻微边框与外环变化。

## 布局

- 空态欢迎语与composer进入同一视觉组，间距控制在24至30px。
- 视觉组位于可用聊天区域垂直中心略偏上，不再贴近底部。
- 桌面端composer最大宽度约880px，空态高度约84px。
- 375px视口使用左右14px安全边距，欢迎语与composer保持紧凑，不横向溢出。
- 消息态布局不受本轮改动影响。

## 顶栏与运行抽屉

- 空态顶栏去掉明显分隔线并降低标题存在感。
- 空态隐藏“运行”和“刷新”文字按钮，主题按钮继续保留。
- `startNewChat()`主动派发抽屉关闭事件，避免空运行面板残留。
- 已有消息或运行记录时，顶栏操作和抽屉功能保持现状。

## Composer

- 降低空态composer高度、阴影扩散和圆角体积。
- 欢迎语字号使用响应式范围，避免大屏过大、窄屏拥挤。
- 模型选择、附件按钮、发送按钮维持现有功能和键盘语义。
- `:focus-visible`保留键盘焦点；普通`:focus`和鼠标点击不显示双层黑框。

## 状态与数据流

- `ChatMessages`继续以`showWelcome`控制`#page-chat.chat-empty`。
- CSS以`.chat-empty`为作用域，不影响已有消息布局。
- 新建会话时，`startNewChat()`清空消息后触发`knowflow:react-drawer-close`。
- 不新增后端接口，不修改会话、模型或Agent运行数据。

## 验证

- 新会话会自动关闭空运行抽屉。
- 桌面端关闭抽屉与展开抽屉两种宽度下，欢迎语和composer保持同组且不偏底。
- 375px视口无横向滚动，按钮和模型名称不溢出。
- 鼠标点击“刷新”、主题按钮、composer不留下双层描边。
- Tab键导航仍能看到清晰焦点。
- 既有消息态、运行抽屉、模型选择器和Skill选择器回归通过。
