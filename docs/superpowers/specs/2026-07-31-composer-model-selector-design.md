# 输入框模型选择器设计

## 目标

在聊天输入框内提供类似Codex的模型切换器。用户始终看得见下一条消息将使用哪个模型，可以在不离开聊天页的情况下切换，并且当前会话、历史会话和新会话之间的选择行为一致。

## 现状

系统已经具备完整的模型选择基础链路：

- `/api/model-configs`返回当前用户自己的模型配置；
- `selectedChatModelConfigId`保存当前前端选择；
- 聊天请求通过`chatModelConfigId`选择模型；
- `chat_session.chat_model_config_id`能够保存会话模型；
- `ChatContextToolbar`已有原生模型下拉框和选择事件。

但`ChatContextToolbar`被CSS隐藏，而且它位于输入行为之外。用户在聊天页看不到当前模型，也无法自然切换。打开历史会话时，前端也没有恢复该会话保存的模型。

## 方案

采用输入框内的模型胶囊和向上弹层，不恢复旧工具栏。

### 输入框胶囊

- 位于输入框内容区下方左侧，与发送按钮形成稳定的底部操作行；
- 显示模型配置名称，例如`GPT-5.5`，不显示接口地址、API Key等敏感信息；
- 无可用聊天模型时显示“配置模型”，点击进入设置页；
- 生成期间保持可见但禁止切换，避免用户误以为切换影响正在执行的请求。

### 模型弹层

- 从胶囊上方向上展开，不遮挡输入内容；
- 只列出`modelType=chat`的当前用户模型；
- 每项主要显示配置名称，次要显示实际模型名和提供商；
- 当前模型显示勾选状态；
- 底部提供“管理模型”，跳转设置页；
- 支持鼠标、触摸和键盘操作：方向键移动，Enter选择，Esc关闭；
- 点击弹层外关闭，选择后自动关闭并将焦点还给输入框。

## 选择语义

### 当前会话

切换模型后，下一条消息立即使用新模型。发送消息时，后端将本次`chatModelConfigId`同步到`chat_session.chat_model_config_id`，使会话模型与最后一次实际使用保持一致。

### 历史会话

会话列表已包含`chat_model_config_id`。打开历史会话时，将该值随会话继续事件传给控制器，再通过现有模型解析器恢复选择。如果模型已删除或不属于当前用户，则回退到第一个可用聊天模型。

### 新会话

新建聊天不重置模型选择，因此继承用户最近一次选择。首次加载且没有选择时，沿用现有解析逻辑选择第一个可用聊天模型。

### 重试与Agent恢复

消息重试和Agent整轮重启继续使用原始请求快照中的`chatModelConfigId`，不会因为用户后来切换模型而悄悄改变历史任务语义。新发送的消息才使用当前胶囊选择。

## 组件与数据流

新增`ComposerModelPicker`，由`ChatComposerForm`渲染。组件监听现有`knowflow:react-model-options-updated`和`knowflow:react-model-selection-updated`事件，并通过`knowflow:react-chat-model-change`提交选择。

数据流：

1. 模型目录刷新，控制器广播用户可用模型和当前选择；
2. `ComposerModelPicker`过滤聊天模型并显示当前值；
3. 用户选择模型，派发模型变更事件；
4. 控制器使用`resolveChatModelConfigId`校验用户选择并更新状态；
5. 下一次`submitChat`将该值写入`chatModelConfigId`；
6. 后端创建会话或更新现有会话的`chat_model_config_id`；
7. 打开历史会话时，侧栏把会话保存的模型ID交给控制器恢复。

不新增模型选择API，不复制模型列表状态到第二套全局store。

## 视觉方向

- **视觉基调：** 单色、紧凑、工具感明确，使用现有输入框材质和边框体系；
- **内容层级：** 当前模型是正文级信息，提供商和实际模型名是辅助辨识，不用小字承担关键状态；
- **交互特征：** 弹层从胶囊上方快速展开，当前项有低对比背景和勾选，按压反馈使用轻微缩放；
- 不增加大标题、说明段、卡片堆叠、渐变装饰或独立模型管理页。

## 响应式与无障碍

- 桌面弹层宽度约300px，限制在composer可视区域内；
- 375px宽度下弹层使用输入框可用宽度，长名称单行省略；
- 胶囊和选项使用真实`button`，弹层使用`listbox`语义；
- 提供`aria-expanded`、`aria-controls`、`aria-activedescendant`和明确的中文标签；
- 焦点样式沿用现有高对比轮廓，不能只依赖颜色表示选择。

## 错误与空状态

- 模型目录加载失败：保留最近有效选择，不打开空弹层；
- 没有聊天模型：胶囊显示“配置模型”，点击进入设置页；
- 当前模型被删除：目录刷新时回退到第一个聊天模型并同步界面；
- 会话保存的模型不可用：回退但不暴露其他用户模型；
- 模型切换本身不发网络请求，真正发送失败继续使用现有聊天错误和运行恢复界面。

## 安全边界

- 只使用后端已经按用户隔离返回的模型配置；
- 前端不渲染`apiKey`，不显示完整接口地址；
- 后端继续通过用户ID校验`chatModelConfigId`；
- 会话模型更新必须限定`session_id + user_id`，跨用户会话返回404；
- 不把模型能力、价格、上下文长度等未经验证的信息写入界面。

## 测试

- 前端契约：组件存在、只过滤聊天模型、事件链路、键盘和空状态；
- 控制器：选择值经过解析器，历史会话恢复模型，新会话保留选择；
- 请求：下一条新消息使用当前模型，历史重试使用原请求模型；
- 后端：现有会话发送后更新模型字段，用户隔离不变；
- 样式：胶囊、向上弹层、当前项、移动端宽度和暗色主题；
- 回归：全部`tests/check_*.py`、npm审计和生产构建。

## 非目标

- 推理强度、速度、温度或Top P快捷设置；
- 自动探测模型能力；
- 每条历史消息旁切换模型；
- 多模型并行回答或模型对比；
- 修改已有模型配置和密钥管理流程。
