# 聊天输入区融合悬浮设计

## 目标

聊天记录与输入框属于同一个连续工作区。移除两者之间的硬分割线和独立底栏感，让输入框与正文共用内容轴，并通过底部渐隐保证滚动内容与输入框自然衔接。

## 布局

- 非空聊天中，消息正文与输入框使用相同的最大宽度和水平边距。
- 输入区覆盖在聊天画布底部，不再绘制顶部分割线。
- 消息列表预留与输入框高度匹配的底部安全区，最后一条消息和复制按钮不能被遮挡。
- 输入区背景从透明渐变为页面底色，滚动内容进入输入框区域时逐渐淡出。
- 输入框保留轻微边框、圆角和低强度阴影；聚焦时只增强边框与阴影，不改变布局。
- 空对话页面继续沿用现有居中布局，不受本次调整影响。

## 交互

- 加号菜单、Skill选择器、已选Skill标签、发送与停止按钮行为保持不变。
- Skill选择器继续锚定输入框上方，不能被聊天滚动容器裁切。
- 文本域增高时，输入区向上扩展，消息安全区覆盖最大输入高度。

## 响应式

- 桌面端正文与输入框最大宽度一致。
- 窄屏下使用统一的左右安全边距，输入框不贴边。
- 375px视口下不得横向溢出，发送按钮、加号和中文占位符保持可用。

## 实现边界

- 优先通过聊天页末尾CSS覆盖完成，不改消息、发送和Skill数据流。
- 不重做输入框组件，不调整侧栏、顶栏、消息Markdown样式和运行面板。
- 同步维护`frontend/styles.css`与React构建使用的样式副本。

## 验收

- 非空聊天中看不到独立底栏分割线。
- 正文左边界与输入框左边界对齐。
- 最后一条长消息滚动到底后完整可见，不被输入框遮挡。
- 输入框聚焦、增高、打开Skill选择器时没有跳动或裁切。
- 桌面和375px视口均无横向滚动。
- 前端结构检查、Skill选择器检查和生产构建通过。
