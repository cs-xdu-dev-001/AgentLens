# LangGraph渐进式迁移设计

## 目标

在不破坏现有聊天、模型选择、联网搜索、MCP、Skills、审批、Mem0记忆和运行面板的前提下，将当前自研Agent循环逐步迁移到LangGraph。

迁移完成后，LangGraph负责真正的执行状态、暂停、恢复和断点续跑；现有`agent_run`、`agent_run_step`和trace继续承担前端展示与审计职责。Windows本地单机版和当前单worker服务器都必须可运行。

## 现状

当前系统已经具备：

- `AgentRunner`模型与工具循环；
- Chat Completions和Responses API；
- 用户级模型选择；
- `web_search`、MCP和Notion OAuth；
- 用户级Skills；
- 写入型工具审批；
- Mem0长期记忆召回与异步整理；
- `agent_run`、`agent_run_step`和SSE运行状态；
- 前端运行面板、失败恢复和浏览器刷新重连。

本次迁移不是重新制作这些功能，而是替换底层执行方式。现有功能、接口和前端行为构成迁移基线。

## 方案选择

### 方案A：渐进式替换

先建立统一执行引擎接口，保留当前执行器，再按纯模型、checkpoint、运行状态、联网搜索、MCP、Skills、审批和记忆的顺序迁移。每个阶段独立验证并可将后续新任务切回当前执行器。

本方案风险最低，也最适合持续部署，采用此方案。

### 方案B：双引擎影子运行

同一请求同时运行当前执行器和LangGraph，对比结果。它会增加模型费用，而且写入型工具不能安全重复执行，仅适合局部诊断，不作为主迁移方式。

### 方案C：一次性整体迁移

直接重写全部流程，短期代码集中，但MCP、审批、记忆和前端状态容易同时回归，不采用。

## 架构边界

新增统一的`AgentEngine`执行入口：

```text
聊天接口
   ↓
AgentEngine
   ├─ CurrentAgentEngine：包装当前AgentRunner
   └─ LangGraphAgentEngine：运行LangGraph
   ↓
标准运行事件
   ↓
现有SSE、agent_run记录和前端运行面板
```

具体边界：

- `CurrentAgentEngine`只包装现有行为，不重写当前循环；
- `LangGraphAgentEngine`独立新增，不在当前循环内部嵌套LangGraph；
- 模型网关、工具注册、MCP、Skills、审批和Mem0继续作为独立服务，由两套执行引擎复用；
- 两套引擎输出相同的标准运行事件；
- 现有API、SSE协议和前端面板在早期阶段保持不变；
- 运行开始时选择执行引擎，整次运行过程中不切换。

初始配置默认使用`CurrentAgentEngine`。LangGraph先只对测试环境或指定测试用户启用，验证稳定后再逐步扩大。

## 状态职责

### LangGraph状态

LangGraph负责决定任务如何继续，保存：

- 当前消息；
- 已完成和待执行的节点；
- 工具调用及结果；
- 审批等待状态；
- 当前模型配置ID；
- 当前Skill快照；
- Mem0操作ID；
- 恢复执行所需的最小上下文。

LangGraph状态不保存API Key、OAuth Token或其他秘密。它只保存配置ID，运行时再通过用户身份读取对应配置。

### 运行展示状态

`agent_run`、`agent_run_step`和trace继续保存：

- 运行状态和当前进度；
- 面向用户的步骤标题；
- 步骤耗时；
- 脱敏输入与结果摘要；
- 公开失败原因；
- 前端右侧运行面板需要的数据。

这些数据是LangGraph执行状态的展示投影，不再独立决定任务从哪里恢复。

### 聊天消息

聊天消息只保存用户与助手最终可见内容。内部节点、完整工具参数和checkpoint不写入聊天正文。

## checkpoint与存储

checkpoint是执行进度存档。LangGraph每完成一个关键节点就保存状态，中断后从最近一次存档继续。

- `thread_id`直接使用现有`run_id`，避免两套运行编号；
- Windows本地单机版和当前单worker服务器先使用LangGraph官方SQLite checkpointer；
- SQLite路径由环境配置指定，数据目录不进入Git；
- 后续如果服务器改为多worker或多实例，再迁移到LangGraph官方Postgres checkpointer；
- checkpoint读取必须同时验证`user_id`与`run_id`的归属；
- checkpoint只保存恢复所需的脱敏数据。

## 标准运行事件

两套执行引擎统一产生以下语义事件：

- 运行开始；
- 模型步骤开始、完成或失败；
- 工具步骤开始、完成或失败；
- 等待审批；
- 审批通过、拒绝或超时；
- 记忆召回开始与完成；
- 记忆整理排队、运行、无变更、完成或失败；
- 运行完成、取消、中断或失败。

事件适配层负责将这些事件更新到现有运行记录并通过SSE发送给前端。前端不需要判断当前使用哪套执行引擎。

## 分阶段迁移

### 阶段1：基线保护

- 固化当前核心行为的回归测试；
- 记录现有测试、构建和真实浏览器流程结果；
- 不修改运行逻辑。

门禁：当前功能和全部检查继续通过。

### 阶段2：执行引擎接口

- 新增`AgentEngine`接口；
- 新增`CurrentAgentEngine`包装当前`AgentRunner`；
- 增加执行引擎配置开关；
- 默认继续使用当前执行器。

门禁：接口响应、SSE事件、数据库记录和前端显示不变。

### 阶段3：最小LangGraph

- 实现用户消息到模型回答的最小图；
- 复用现有模型配置和用户选择；
- 同时兼容Chat Completions和Responses API；
- 暂时不加载工具。

门禁：测试用户可以使用LangGraph连续对话，当前用户不受影响。

### 阶段4：checkpoint与恢复

- 接入SQLite checkpointer；
- 建立`run_id`与`thread_id`的一一对应；
- 验证服务中断、浏览器刷新和恢复执行；
- 验证用户隔离。

门禁：任务可以从最近checkpoint继续，而不是从头执行。

### 阶段5：运行状态接轨

- 将LangGraph节点事件转换为标准运行事件；
- 更新现有`agent_run`、`agent_run_step`和trace；
- 保持现有SSE与前端运行面板协议。

门禁：模型、工具、等待、完成和失败状态能实时显示并最终收敛。

### 阶段6：联网搜索

- 迁移只读的`web_search`；
- 建立模型选择工具、执行工具、返回结果和继续回答的循环；
- 复用现有Tavily配置与脱敏规则。

门禁：模型可以自主判断是否搜索，工具结果正确进入回答和运行面板。

### 阶段7：MCP与Skills

- 先迁移只读MCP工具，再接入可能写数据的工具；
- 复用MCP连接、OAuth、工具发现和用户隔离；
- 复用Skill选择、快照和允许能力范围。

门禁：Notion读取、Skill选择、工具发现和用户隔离正常。

### 阶段8：审批暂停与继续

- 使用LangGraph`interrupt`暂停写入型工具；
- 用户批准后从checkpoint继续；
- 处理拒绝、超时、重复提交和服务重启。

门禁：等待审批期间刷新页面或重启服务后仍可继续原任务，工具不会重复执行。

### 阶段9：Mem0记忆

- 回答前执行长期记忆召回；
- 回答后异步整理长期记忆；
- 映射排队、运行、无变化、完成和失败状态；
- 保留用户开关与用户隔离。

门禁：有变更、无变更、失败和关闭记忆四种路径都能结束，不出现永久等待。

### 阶段10：可靠性、灰度与清理

- 补齐取消、重试、超时和重复请求保护；
- 先测试用户、再部分用户、最后全部用户启用LangGraph；
- 保留快速切回当前执行器的配置；
- 满足删除条件后再移除当前`AgentRunner`循环。

门禁：LangGraph覆盖全部现有能力，持续运行稳定，当前执行器回退开关在观察期内未被使用。

## 幂等与重复执行

“幂等”表示同一个工具调用被意外重试时，不会重复创建或重复修改外部数据。

- 每个工具调用在真正执行前生成稳定的调用ID；
- checkpoint保存调用ID和已完成结果；
- 恢复时先检查该调用是否已有结果；
- 写入型MCP工具不得在未知结果状态下自动重放；
- 无法确认外部执行结果时，任务进入明确的人工确认状态。

## 错误与回退

- LangGraph失败后不自动改用当前执行器重新执行同一任务；
- 失败节点、公开错误码和脱敏摘要写入checkpoint与运行投影；
- 用户可以从安全的失败节点重试，或明确创建新的当前执行器任务；
- 配置开关只影响后续新任务，不改变正在执行的任务；
- 每个迁移阶段独立提交，门禁失败时停止推进，不回滚无关修改。

## 安全边界

- checkpoint不保存API Key、OAuth Token、Cookie、请求头或原始私有工具输出；
- 所有模型、MCP、Skill、记忆和运行查询继续校验登录用户；
- 用户提供的配置通过ID引用，不复制到图状态；
- 运行事件只包含前端需要的公开摘要；
- 数据库、checkpoint、上传文件和构建产物不进入Git。

## 测试与发布门禁

每个阶段都必须执行：

- 阶段对应的单元测试和接口检查；
- 全部`tests/check_*.py`；
- `frontend npm run build`；
- `git diff --check`；
- 敏感信息和生成文件检查；
- 当前执行器完整回归；
- LangGraph专项测试；
- 真实浏览器流程验收。

生产发布必须继续遵守测试失败不重启的部署门禁。

## 当前执行器删除条件

只有同时满足以下条件，才允许删除当前`AgentRunner`循环：

- LangGraph覆盖现有全部功能；
- 全量测试与真实浏览器验收通过；
- 生产灰度期没有必须切回当前执行器的问题；
- 审批恢复、写入型工具幂等和Mem0状态收敛已验证；
- Windows本地单机安装和服务器部署均已验证；
- 删除动作单独提交，可清晰审查。

## 非目标

- 本次不引入Temporal等额外工作流平台；
- 本次不改造前端视觉；
- 本次不将服务器立即改为多worker或多实例；
- 本次不重写模型、MCP、Skills和Mem0服务；
- 本次不保存或展示模型私有推理过程；
- 本次不在第一阶段迁移任何工具。
