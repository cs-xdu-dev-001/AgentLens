# Agent运行恢复设计

## 目标

在现有持久化运行、停止、刷新重连、计划续跑和整轮重跑能力上，补齐清晰的失败分类与可操作恢复界面。用户不需要理解内部状态机，也能知道失败原因、是否适合继续、应该检查哪个配置。

## 现状与缺口

当前系统已经具备：

- `agent_run`和`agent_run_step`持久化；
- 运行中停止和审批取消；
- 服务重启后的`interrupted`恢复；
- 计划任务从失败步骤继续，已完成步骤自动跳过；
- 非计划任务通过消息重试重新运行整轮；
- 浏览器刷新后重新订阅运行事件。

缺口不在执行能力，而在失败信息和恢复入口：计划步骤通常只保存`agent_step_failed`，右侧运行栏无法区分模型认证、MCP授权、限流、超时和普通工具失败，用户必须自行猜测下一步。

## 方案选择

### 方案A：任意步骤独立重放

为每个trace步骤新增重放端点。优点是操作粒度细；缺点是写入型MCP工具可能重复创建、删除或修改外部数据，而且trace步骤没有完整重放上下文。本轮不采用。

### 方案B：复用现有恢复路径并增加失败语义

后端保留具体错误码和固定的公开摘要，运行快照派生`failure`恢复元数据。前端在当前运行栏展示原因和建议，并调用已有`resume`、消息重试、页面导航。该方案不改变任务执行语义，也不会盲目重放写入型工具。本轮采用。

### 方案C：检查点与补偿事务

为所有工具增加幂等键、检查点和补偿动作。适合未来的长任务工作流，但涉及工具协议、MCP注解和外部系统一致性，超出本轮范围。

## 后端设计

新增独立的失败分类模块，将异常或工具错误码归一为公开恢复信息：

- `model_authentication_failed`：检查模型配置；
- `mcp_authentication_required`：重新授权MCP；
- `rate_limited`：稍后继续或重跑；
- `upstream_timeout`：从失败步骤继续；
- `service_restart_interrupted`：继续执行；
- `web_search_timeout`：继续执行；
- 其他错误：保留脱敏错误码，使用通用公开摘要。

分类结果只包含固定摘要，不回传原始异常、请求头、密钥、Token或完整上游响应。

计划步骤失败时，保存具体`errorCode`和公开`outputSummary`，不再统一覆盖成`agent_step_failed`。根trace失败时也保存同一公开摘要。`AgentRunStore`根据失败步骤或失败trace派生：

```json
{
  "failure": {
    "code": "upstream_timeout",
    "summary": "The upstream service timed out.",
    "retryable": true,
    "target": null
  }
}
```

不增加数据库列。公开摘要写入现有步骤`output_summary`和trace，旧数据库可直接兼容。

## 前端设计

在右侧运行栏概览下方增加紧凑恢复面板，只在`failed`、`interrupted`或`cancelled`状态显示：

- 中文失败原因；
- 脱敏错误码；
- 当前失败步骤与尝试次数；
- 主操作：有持久化计划时显示“从失败步骤继续”，无计划时显示“重新运行本轮”；
- 次操作：始终允许“重新运行本轮”；
- 上下文操作：模型错误显示“检查模型配置”，MCP错误显示“重新授权”，记忆错误显示“管理长期记忆”。

视觉沿用当前运行栏：扁平边框、状态色点、正文级字号，不增加大标题、说明卡片堆叠或新页面。动作按钮仅在当前状态允许时出现。

## 数据流

1. 执行异常进入失败分类器。
2. 计划步骤和根trace保存具体错误码与公开摘要。
3. `GET /api/agent/runs/{id}`和SSE快照返回派生的`failure`。
4. 前端恢复面板根据`failure.target`和运行结构显示动作。
5. “从失败步骤继续”调用现有`POST /resume`，执行器跳过已完成步骤。
6. “重新运行本轮”调用现有消息重试事件，创建新的运行。
7. 配置动作只导航到对应页面，不自动修改配置或重新授权。

## 安全边界

- 不提供写入型工具的独立重放；
- 不回传原始异常和上游响应正文；
- 不显示API Key、OAuth Token、请求头或私有工具输出；
- 用户隔离继续由现有run查询和操作接口保证；
- 恢复动作必须符合当前运行状态，非法状态仍返回409。

## 测试

- 后端失败分类：认证、MCP授权、限流、超时、未知错误；
- 运行快照：失败步骤优先、trace回退、无失败时不返回`failure`；
- 执行路径：具体工具错误码不再被`agent_step_failed`覆盖；
- 前端：恢复面板状态、目标导航、resume和整轮重跑事件；
- 回归：停止、审批、计划续跑、刷新恢复和全部`tests/check_*.py`。

## 非目标

- 任意工具步骤的无条件独立重放；
- 自动修改模型或MCP配置；
- 分布式任务队列、跨节点协调和补偿事务；
- 保存或展示私有chain-of-thought。
